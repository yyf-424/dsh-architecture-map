# n15 — Remote indexer

## Responsibility

Keep a tracked remote project's local status current without pulling source:
poll a cheap fingerprint, run the existing manifest-only sync when it changes,
write `remote-state.json`, and hand the change counts to the maintainer.

## Files

- `src/host/remote/indexer.js` — `createRemoteIndexer({ memory, maintainer })`.
- `src/host/remote/state.js` — atomic `remote-state.json` read/write.

## Behavior

- `track(ws, context)` starts one polling loop per project; `untrack`/`dispose`
  clear timers.
- The first check records a baseline only. `arch_sync` is not run and nothing
  is marked stale on first contact.
- An unchanged digest only updates `lastCheckedAt`.
- A changed digest runs `memory.sync(ws, { markStale: true })`, records pending
  added/changed/deleted counts, and passes the counts to the maintainer.
- Errors set `lastError` and back off exponentially up to 15 minutes.
- `check()` is also called directly by `/arch remote sync`.

## Invariants

- Polling reads fingerprints and hashes; it never sends remote content to the
  model and never writes a remote file.
- `remote-state.json` stays inside the local project state directory.
- One timer and one in-flight check per project; disposal stops rescheduling.
