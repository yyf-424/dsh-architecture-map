# n16 — Remote maintainer

## Responsibility

Decide whether a detected remote change may start an automatic maintenance
child, and build the child's remote-only instructions. The plugin supplies the
actual `startChild`; this module owns consent, size, cooldown and single-flight
policy.

## Files

- `src/host/remote/maintainer.js` — `createMaintainer`, `buildMaintainerPrompt`.

## Policy

- A durable workspace grant (`consent.autoMaintenanceAllowed`) is required;
  session-only consent is never enough.
- Zero changes → no child. More than 50 changed files → no child.
- At most one maintenance child per project at a time; a ten-minute cooldown
  applies unless `/arch remote update` explicitly forces a run.
- A missing parent agent or subagent service fails cleanly.

## Child prompt

The prompt names `remote:<id>` and `host:root`, lists the change counts, tells
the child to call `arch_sync`, read only changed files through
`arch_remote_read`/`arch_remote_grep`, never use local file tools, commit the
manifest and never write remote files.
