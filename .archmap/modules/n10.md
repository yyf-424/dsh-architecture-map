# n10 — Content source

## Responsibility

One read-only contract for everything the graph and memory stores need from
workspace files: walk the tree, hash anchors, describe a commit candidate, and
serve bounded text reads. Local and remote implementations share the contract;
the rest of the Host never calls `node:fs` for workspace content.

## Files

- `src/host/content/index.js` — `ContentError`, `contentFail`, exports.
- `src/host/content/local.js` — `createLocalContent(root, options)`.

## Contract

| Method | Result |
|---|---|
| `listTree(limit?)` | `{ entries: [{ path, size }], truncated }` |
| `scan({maxFiles,maxFileBytes})` | `{ files: Map<path,{sha256,size,signature}>, truncated, skipped }` |
| `hashMany(paths)` | `Map<path, hash>` (local: normalized signature) |
| `describe(rel,{maxFileBytes})` | `{kind:'text'|'binary'|'oversized'|'not-file'|'missing', size?, sha256?, signature?}` |
| `readText(rel,{maxBytes})` | text or null |
| `readRange(rel,{offset,length})` | `{ text, offset, bytes, eof }` |
| `stat(rel)` | `{ type, size }` or null |

## Invariants

- The local `scan` is byte-identical to the pre-refactor memory scan: same
  ignored directories, binary extensions, size cap, sha256 and normalized
  signature.
- `.git`/`.archmap`/`node_modules` entries are skipped even when `.git` is a
  worktree pointer file.
- Every path is workspace-relative POSIX and confined to `workspaceRoot`;
  missing files yield no hash rather than a fabricated one.
- No write operations; the content source is read-only.
