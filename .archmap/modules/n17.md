# n17 — Remote commands

## Responsibility

The user-driven `/arch remote ...` surface. Commands may change the project
index or consent; model tools may not.

## Files

- `src/host/remote/commands.js` — `createRemoteCommands`, `splitArgs`.
- `src/host/plugin.js` — routes `/arch remote ...` before the discuss branch.

## Commands

| Command | Behavior |
|---|---|
| `add <id> <host> <path>` | validates host/path, probes vcs, writes the remote project |
| `list` | lists local + remote projects with consent/vcs |
| `select <id>` | starts the indexer poller for this project |
| `sync <id>` | one fingerprint check + manifest-only sync |
| `update <id>` | checks, then starts the maintenance child (force bypasses cooldown) |
| `grant <id>` | writes durable workspace consent |
| `revoke <id>` | clears session + workspace consent |
| `remove <id> [--purge]` | removes the project; `--purge` deletes local state |

## Invariants

- Adding a host is a user command, not a model tool.
- `add` refuses duplicate ids and unvalidated host/path values.
- `remove` keeps local state unless `--purge` is explicit.
- Command errors return `{ kind: 'error', text }`; they never throw to the
  composer.
