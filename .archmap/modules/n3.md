# n3 — Memory store

- **Anchor:** `src/host/memory.js#createMemoryStore`
- **Group:** `g-host`
- **Kind:** module

Builds the file manifest, classifies local code vs cosmetic changes via the normalized signature, reports affected nodes, marks stale status and refreshes anchors. Also serves the `overview` / `modules` / `notes` dossier.

File access goes through the content source (n10/n12):
- Local projects scan every scannable file (`sha256` + signature).
- Remote projects list paths with `listTree`, then hash only the files already in the manifest; new/deleted paths come from the tree delta. No remote content is transferred for sync, and a remote manifest entry has no normalized signature, so remote cosmetic detection is intentionally conservative (any content change is a code change).
- Anchor hash mismatch compares `signature ?? sha256`, which lets local signature anchors and remote sha256 anchors coexist.
- `arch_manifest_commit` describes each requested file in place, so remote commit records sha256/size without pulling content.
