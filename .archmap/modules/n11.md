# n11 — Remote transport

## Responsibility

Own one read-only OpenSSH command recipe: fixed options, optional ControlMaster
reuse, bounded concurrency, per-command timeout, abort handling, output caps,
POSIX quoting and a small capability probe. It never invents a remote command
that writes; callers pass the exact command or argv.

## API

- `createSshClient({ host, binary?, ... })` → `{ run, exec, execShell, probe }`
- `exec(argv, opts)` quotes every argument with single quotes and joins it into
  one remote command.
- `execShell(script, opts)` is for trusted internal scripts only; callers must
  quote every interpolated value.
- `probe()` reports `{ os, git, sha256sum, shasum, rg, find, stat }`.
- Errors carry stable codes: `SSH_TIMEOUT`, `SSH_ABORTED`, `SSH_OUTPUT_LIMIT`,
  `SSH_CONNECTION_FAILED`, `SSH_HOST_KEY`, `SSH_HOST_UNKNOWN`,
  `SSH_COMMAND_FAILED`, `SSH_UNAVAILABLE`.

## Invariants

- `BatchMode=yes`, `ConnectTimeout`, `ServerAliveInterval`; never overrides
  `StrictHostKeyChecking` and never stores credentials.
- Host must not start with `-` or contain whitespace; remote roots are absolute
  POSIX paths with no `..` or control characters.
- A command that exceeds its timeout, its output cap or its abort signal is
  killed; the error is reported instead of partial output.
- No remote write verbs exist in this module.

## Status

W3 verified: 7 transport tests plus the full 24-test suite pass against a local
fake SSH; quoting, capability probe, auth failure, non-zero exit, timeout,
abort and output cap are covered. Remote content consumes this in W4.
