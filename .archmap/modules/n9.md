# n9 — Project index

## Responsibility

Turn a tool's `workspace` value into one descriptor: where the code lives
(`workspaceRoot`), where the graph/dossier state lives (`stateDir`), and which
content source reads the code. One `.archmap` directory can hold the legacy
local project plus remote projects.

## Files

- `src/host/projects.js` — `index.json` schema, project validation, atomic
  writes, `remote:<id>` ids, and the implicit local project.
- `src/host/workspace.js` — `resolveWorkspace(raw, context, config)`:
  - local absolute path → `stateDir = <root>/.archmap`, local content source;
  - `remote:<id>` → hub is the calling session cwd, state is
    `<hub>/.archmap/projects/<id>`, content root is the registered remote root
    (remote content source is wired in W4).

## Invariants

- No `index.json` means the legacy local-only layout; existing repositories
  need no migration.
- The local project keeps `.archmap/graph.json`; remote projects use
  `.archmap/projects/<id>/`.
- Project ids match `[a-z][a-z0-9_-]{0,63}` and `local` is reserved.
- A project `dir` is workspace-relative POSIX with no empty, `.` or `..`
  segments; the resolved state directory must stay under `.archmap`.
- `remote:<id>` fails closed without a session working directory, an index, or
  a matching remote entry.
