# n14 — Remote read tools

## Responsibility

The model-facing way to inspect a remote project: list projects, report status,
list paths, read a file with line numbers and grep. List and status are
metadata-only; tree/read/grep pass the consent gate before touching content.

## Files

- `src/host/remote/tools.js` — `createRemoteTools({ config, consent })`.
- `src/host/plugin.js` — registers `arch_remote_list/status/tree/read/grep`.

## Behavior

| Tool | Consent | Notes |
|---|---|---|
| `arch_remote_list` | no | reads `.archmap/index.json`; local + remote projects |
| `arch_remote_status` | no | vcs, HEAD/dirty or non-git digest, consent scope; no paths |
| `arch_remote_tree` | yes | capped path listing |
| `arch_remote_read` | yes | numbered lines, offset/limit, binary/oversize errors |
| `arch_remote_grep` | yes | rg/grep, include/path/context/max results |

## Invariants

- A rejected, skipped or unavailable consent answer yields a clear
  `REMOTE_CONSENT_*` error and zero content.
- Status never returns file paths or contents; list never returns contents.
- Paths are remote-root-relative; unsafe paths are rejected by the content
  source.
- Remote discussion children inherit the parent session grant and are denied
  local `read`/`grep`/`glob` plus the usual shell/write tools.
